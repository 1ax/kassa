# Касса

Пробитие кассовых чеков и чеков коррекции на ККТ Штрих-М-02Ф напрямую с macOS,
по TCP, без Windows и драйвера ДТО.

ФФД 1.05. Протокол ККТ v.1.18 (спецификация Штрих-М от 21.01.2025).

## Установка

Один раз:

```bash
cd /Volumes/tera/dev/kassa
./packaging/install_app.sh
```

В Программах появится **Касса** с иконкой. Дальше — только клик по ней:
поднимется сервер и откроется браузер на `http://127.0.0.1:8765`.
Повторный клик второй сервер не плодит — просто открывает вкладку.
Виртуальное окружение и зависимости лаунчер поставит сам при первом запуске.

Порт фиксированный, так что адрес можно положить в закладки Safari —
он не поменяется. Выключается касса кнопкой «Выключить кассу» внизу левой
колонки; из терминала то же самое делает `python app.py --stop`.

Если что-то не поднялось, лаунчер покажет диалог с последними строками
`kassa.log` из папки проекта.

## Запуск из терминала

```bash
source .venv/bin/activate
python app.py
```

| Ключ | Зачем |
|---|---|
| `--port 9123` | взять конкретный порт |
| `--strict-port` | не искать свободный, упасть если занят |
| `--demo` | работать на эмуляторе: ничего не печатается, касса не нужна |
| `--open` | открыть браузер сразу после старта |
| `--stop` | погасить уже запущенную кассу |

Порт по умолчанию — **8765**, а не 8000: восьмитысячный занимает половина
локальных сервисов, а 5000 и 7000 на macOS держит AirPlay из Control Center.
Если порт занят посторонним сервисом, сервер скажет об этом и возьмёт
следующий свободный; с `--strict-port` — откажется стартовать.

Слушается только `127.0.0.1`, и запросы с чужим именем хоста отбиваются:
интерфейс доступен с этого компьютера и ни с какого другого.

## Настройки

Адрес кассы, порт и пароли лежат в `config.json`. Он создаётся при первом
запуске по образцу `config.example.json`, в репозиторий не идёт (там пароли)
и пишется с правами 600. Править можно прямо в файле или в блоке
«Подключение» внизу страницы.

Если адрес не задан, интерфейс скажет об этом прямо и раскроет нужный блок,
а не будет молча показывать «нет связи».

## Посмотреть, не трогая кассу

```bash
python app.py --demo --open
```

Эмулятор держит смену, номера чеков и ФД в памяти. Можно открыть смену,
пробить чек, снять Z-отчёт — интерфейс отработает целиком, бумага не поедет,
в ОФД ничего не уйдёт.

| Файл | Что делает |

| `shtrih.py` | Протокол: рукопожатие, кадры, LRC, обмен по TCP, команды ККТ |
| `app.py` | HTTP-сервер, проверки перед отправкой в кассу, замок на доступ |
| `demo.py` | Эмулятор ККТ для `--demo` |

| `tests/` | Протокольные тесты на эталонных кадрах + тесты API на эмуляторе |
| `config.json` | Адрес, порт, пароли (создаётся при первом запуске) |
| `packaging/` | Иконка и сборка Kassa.app для Программ |

Живая касса им не нужна.

## Что проверено на живой кассе, а что нет

Проба выполнялась на ККТ **Штрих-М-02Ф**, прошивка C1 сборка 62922
от 10.01.2025, протокол 1.14, по TCP.

**Проверено — обмен и чтение состояния:**

* рукопожатие ENQ → NAK → кадр → ACK → ответ;
* разбор ответов `10h`, `11h`, `FCh`, `FF01h`, `FF39h`, `FF40h`. Дата и время
  ККТ сошлись с настенными часами, заводской номер — с шильдиком, номер ФН —
  16 цифр без мусора, ИНН прошёл контрольную сумму, состояние смены сошлось
  сразу по трём независимым командам.

**Не проверено — ничего из того, что печатает.** Открытие смены, X- и
Z-отчёты, `8Dh`, `FF46h`, `FF45h`, `FF35h`/`FF0Ch`/`FF4Ah` на живом ФН
не прогонялись ни разу. Длины кадров сверены со спецификацией (160 / 182 / 69
байт) и закреплены тестами, но это проверка арифметики, а не поведения кассы.

## Первый запуск: порядок обкатки

Идти строго по шагам, не перепрыгивая. Каждый следующий шаг опаснее предыдущего.

1. **Приборная панель.** Лампа должна загореться зелёным, поля заполниться:
   номер ФН, часы кассы, режим, модель аппарата. Это только чтение —
   ничего не меняет.
2. **X-отчёт.** Первая команда, что-то печатающая, но нефискальная.
   Если бумага поехала — транспорт и пароли в порядке.
3. **Открыть смену.**
4. **Чек на 1 рубль.** Наличными, одна позиция. Сверить бумажный чек
   с превью ленты в интерфейсе — они должны совпасть.
5. **Чек коррекции на 1 рубль.** Только после того, как обычный чек лёг ровно.

Если на шаге 4 чек ушёл не так, как задумано, — закрывать смену Z-отчётом
и разбираться до того, как трогать коррекцию.

Если касса ответит непонятной ошибкой, откройте внизу страницы
«Журнал обмена с кассой» — там кадры последней операции в hex.

## О чём стоит знать заранее

**Рукопожатие обязательно.** Перед каждым кадром хост шлёт ENQ и ждёт NAK.
Без этого касса отвечает NAK на кадр и команда теряется — в первой версии
из-за этого молча пропадала первая команда в каждом соединении.

**Пароли.** По умолчанию 30 — это пароль системного администратора у Штрих-М.
Команды печати позиций идут под паролем оператора, фискальные операции и
отчёты — под паролем сисадмина. В блоке «Подключение» они задаются раздельно.

**Налоги.** Код исходит из того, что в таблице 1 кассы режим начисления
налогов = 0, то есть НДС касса считает сама. Если у вас режим 1, суммы
налогов обязан передавать хост — тогда в `close_receipt()` и `correction()`
нули придётся заменить реальными суммами.

**Часы кассы.** Дату и время в фискальный документ ставит касса, а не
компьютер. Если часы разошлись больше чем на 5 минут, поле «Часы кассы»
подсвечивается — это повод зайти в настройки ККТ до того, как пробивать.

**Чек коррекции необратим.** Он уходит в ОФД и отменить его нельзя.
Основание (описание, дата, номер документа) передаётся тегом 1174 —
для ФФД 1.05 это обязательный реквизит, без него налоговая вправе
не признать коррекцию. Сервер не выпустит коррекцию без описания.

**Открытый чек.** Если позиция не прошла, `app.py` сам вызывает
аннулирование, чтобы касса не осталась с открытым документом.
Если что-то всё же зависло — кнопка «Аннулировать чек» на панели,
а приборная панель поднимет тревогу про открытый чек.

**Двойное пробитие.** Пока касса печатает, все кнопки заблокированы:
второй клик по «Пробить» — это второй фискальный чек, а отменить его нельзя.
Одновременные запросы к кассе сериализованы замком на стороне сервера.

**Смена длиннее 24 часов.** Касса перейдёт в режим 3 и откажется пробивать,
пока не снимете Z-отчёт. Режим виден на приборной панели.

**Прокси в окружении.** Если стоит `HTTP_PROXY`, обращения к своему же
серверу на `127.0.0.1` уедут в прокси и вернутся ошибкой. И `app.py --stop`,
и лаунчер ходят мимо прокси явно — но если будете дописывать свои проверки,
не забудьте про это.

**Названия ошибок.** Команда `6Bh` «возврат названия ошибки» на этой прошивке
не поддерживается — отвечает собственной ошибкой `0x37`. Поэтому в интерфейс
попадает голый код ошибки ККТ; расшифровку смотреть в спецификации.
